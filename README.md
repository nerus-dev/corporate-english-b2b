# Corporate English B2B

Самостоятельная армяноязычная scroll-driven презентация для устной защиты по «Управлению проектами»: 11 сцен от идеи услуги до ожидаемого запуска за 6 недель. По прямому запросу пользователя используется название MekStep, его логотип и фирменные цвета. Это учебное предложение новой услуги: 2 пилота и 1+ платящий клиент — цели плана, а не состоявшиеся результаты или подтверждённые факты о MekStep.

## Запуск

Для разработки нужны Node.js 24 и npm. Для запуска готового dist достаточно Node.js. Выполните в каталоге проекта:

```sh
npm ci --ignore-scripts
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

Откройте [презентацию](http://localhost:4173) и [заметки докладчика](http://localhost:4173/speaker-notes.html). Сервер использует порт `4173` или значение переменной среды `PORT`. Для остановки нажмите Ctrl+C.

После изменений повторите сборку. Сервер отдаёт `dist`, а не исходники. В `dist/index.html` используются относительные ссылки: открытие через `file://` предусмотрено, но пока не подтверждено браузерной проверкой. Предпочтительный проверяемый способ запуска — локальный сервер.

## Управление и содержание

- На большом экране сцена остаётся на месте: прокрутка управляет появлением, движением и сменой материалов внутри единого экрана, а не перемещением страниц. Переходы плавно растворяют предыдущую композицию и раскрывают следующую; движение вверх обращает историю. Нативная прокрутка сохраняется.
- ArrowDown / PageDown — следующая сцена; ArrowUp / PageUp — предыдущая.
- Home — начало; End — финал. Перезагрузка возвращает начало.
- На мобильных экранах и при системном reduced motion используется читаемое представление без тяжёлой анимации.
- `dist/speaker-notes.html` содержит полные пояснения к 11 сценам, SMART, 11 задач, все 8 критериев завершения, scope и риски; страницу можно распечатать средствами браузера.

Фирменная палитра MekStep: зелёный `#65CB5E`, чёрный и белый. Зелёный взят из существующего `brand-colors.json` и является оценкой по исходному JPEG, а не подтверждённым значением из брендбука. Используются подлинные локальные изображения логотипа; бизнес-данные и код других проектов не переносятся. Основной фон белый; текст тёмный и контрастный, в том числе на зелёных акцентах. Фиксированная сценическая область и scroll-driven история сохраняются.

Название организации меняется единственной константой `CONTENT.organization` в `src/content.js`. В этом же файле находятся тексты, метрики и заметки. После изменения выполните `npm run build`. Требования и критерии приёмки закреплены в `ARCHITECT.md`.

## Устройство и проверки

HTML/CSS/JavaScript, локальные GSAP 3.13.0 и ScrollTrigger, SVG. `src/main.js` создаёт сцены и анимацию, `src/navigation.js` содержит чистую логику навигации, `src/styles.css` — оформление и адаптацию. `scripts/build.mjs` собирает автономный `dist` и заметки. `scripts/serve.mjs` — простой статический HTTP-сервер. Backend, runtime API, база данных и интеграции отсутствуют.

`npm run lint` проверяет только синтаксис JavaScript через `node --check`; это не полноценный стилистический линтер. `npm run typecheck` проверяет JavaScript с JSDoc и реальными декларациями типов GSAP. `npm test` запускает 6 групп Node.js-тестов: навигация и граничные случаи; контент и ожидаемые цели; создание 11 сцен; сборка и локальные ресурсы; полнота заметок; HTTP-сервер, HEAD, 404 и отклонение обхода каталога. При тестировании также создаётся `dist` и кратковременно запускается сервер на свободном порту.

### Воспроизводимый браузерный checklist

1. После сборки запустить сервер, открыть страницу при 1366×768 и 1920×1080; последовательно просмотреть все сцены вниз и вверх. Проверить, что сцена остаётся в пределах одного экрана и материалы сменяются анимацией без пролистывания страниц; проверить обратимость переходов, армянские буквы, переносы, пересечения текста и линии, подлинный логотип и цвета MekStep.
2. Проверить обе пары клавиш следующей/предыдущей сцены, Home и End; перезагрузить страницу в середине и в конце — должна открыться начальная сцена.
3. На ширине 390 px проверить читаемость и отсутствие горизонтальной прокрутки всей страницы.
4. Включить `prefers-reduced-motion: reduce`, перезагрузить и убедиться, что доступны все задачи, недели, объяснения и финал. Повторить при DPR 2.
5. В DevTools проверить Console и Network: нет ошибок JavaScript, пропавших ресурсов и внешних runtime-запросов. Открыть заметки и проверить полную формулировку SMART, 11 задач и 8 критериев.
6. Проверить автономность отдельно: открыть `dist/index.html` через `file://` и затем отключить сетевое подключение. Для HTTP-страницы не путать блокировку самого localhost в DevTools Offline с внешней зависимостью; проверять отсутствие внешних запросов и работу уже загруженного документа. Записать фактический результат.
